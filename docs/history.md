# История

Здесь два списка: решения с причинами и журнал чатов. Claude не читает файл в начале чата: ищет в нём, когда нужно понять, почему решили именно так (`grep -n`).

## Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 3.11.2026 | Название — Shift Time | Прямо называет главную механику (Shift); рыбы в геймплее пока нет |
| 3.11.2026 | Движок Godot 4.7, GDScript, 2D | Как в Crown: команда знает инструмент, тесты headless |
| 3.11.2026 | Не пытаться обращать произвольную физику | Месяца не хватит; управляемые записываемые объекты предсказуемее |
| 3.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** время мира одно на комнату | Проще проверить базовую механику; независимые поля отложены |
| 3.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** ветвится вся комната | Достаточно для MVP: обрезаем будущее целиком, меньше граничных случаев |
| 3.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** объект, пришедший назад на место игрока, ждёт, пока игрок отойдёт | Игрока не раздавить: не придётся решать столкновения в обратном времени |
| 3.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** игрок не толкает объекты, только точки взаимодействия | Толкание обратимого предмета слишком сложно для месяца |
| 3.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** при удержании Shift связанные объекты подсвечиваются линией | Причину можно увидеть без текста; снимает вопрос «как игрок узнаёт причину» |
| 4.11.2026 | Сеттинг: уставшее будущее, как старые части комплекса в Portal и Half-Life (не белые камеры); ржавая среда, внутри неё работающая техника | Контраст «старое / новое» помогает читать загадки: подчиняется времени то, что принадлежит новому слою |
| 4.11.2026 | Стиль: силуэты и геометрический минимализм | Читаемость головоломок и посильный объём для двоих за месяц |
| 4.11.2026 | Арт: человек даёт основу, нейросеть доводит | Нет художника; геометрия, коллизии и временные объекты остаются за нами, чтобы состояния проигрывались вперёд и назад |
| 4.11.2026 | У персонажа устройство на руке, техника в мире: платформы, машины, механизмы | Индикатор времени становится деталью мира |
| 4.11.2026 | Устройство на руке только включает обратный ход мира, а у владельца время идёт как обычно | Подтверждено командой; объясняет без текста, почему игрок единственный не откатывается |
| 4.11.2026 | Циан только у особых механизмов и предметов, связанных со временем; обычные вещи мира разворачиваются во времени без подсветки | Уточнение команды; один сигнал, который игрок учится читать |
| 4.11.2026 | Платформы и стены почти ровные; рваными остаются только потолок и пролом | Замечание команды по концепту: платформы «не надо так изкревлять», потолок «супер» |
| 4.11.2026 | Ржавых потёков много: от краёв платформ, потолка, швов стены и трубы | Команде понравились потёки, просьба «ещё» |
| 4.11.2026 | Персонаж: присел и наклонён к рычагу, короткие руки, шарф двух цветов, силуэт проще | Замечания команды по версиям 2 и 3 концепта: «длиннорукий», «чуть проще» |
| 5.11.2026 | Узлы-синглтоны лежат в `game/autoload/`, а не в `core/` | Правило проекта: `core/` не наследует `Node` |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** воспроизведение вместо пересчёта; симуляция только на голове истории | Ветвление получается само, детерминизм проще проверить |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** при зажатом Shift мир закрепляется на кадре 0 | Решение не зависит от тайминга, игрок действует без спешки |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** предыстория уровня (`prelude_seconds`) | Без истории до появления игрока уровням со следствием нечего откатывать |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** кадр на каждом физическом тике (60/с), запасной вариант 15/с с интерполяцией | Проще и точнее; данных для 10–30 объектов мало |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** при столкновении с игроком весь мир замирает на этом тике | Одно время на комнату; проще, чем замирание отдельного объекта |
| 5.11.2026 | **Предложено Claude, подтверждено 5.11.2026:** окна действия не короче 3 с | Правило «решение без угадывания тайминга» |
| 5.11.2026 | Комнаты шире экрана, камера следит за игроком (ответ на вопрос 6, раздел 11 architecture.md) | Подтверждено командой; уровни не придётся переделывать, когда они вырастут |
| 5.11.2026 | Предыстория скриптуется через `simulate_tick()` без игрока; отдельных `Branch`, `BranchManager` и `TimelineManager` нет: ветка — метод `Timeline.branch()`, роль менеджера у `TimeWorld` (вопросы 3–5, раздел 11) | Команда разрешила обойтись без отдельного менеджера и просила держаться концепции: время игрока линейно, мир по Shift идёт назад. Вопрос 3 решил Claude в этих рамках |
| 5.11.2026 | Данные читает статический `Content` (`core/content.gd`), автозагрузки `game_data.gd` пока нет | Автозагрузки недоступны по имени в тестах через `--script`; `Content.validate()` проверяет JSON, как в Crown |
| 5.11.2026 | Блоки тестовой комнаты лежат в `game/levels/blockout/` и собираются `tools/build_blockout.gd` | Сцена остаётся обычной, с `TileMapLayer`; карту легко пересобрать. задача 1.5 заменит серые блоки |
| 5.11.2026 | Слои физики: 1 «world», 2 «player» | Игрок сталкивается только с миром; временные объекты позже получат свои слои |
| 6.11.2026 | `TimeManager` читает `Input.is_action_pressed("rewind")` на каждом физическом тике, а не события клавиши; приоритет физики −100 | Тесты решений уровней нажимают действия через `Input.action_press`, событий нет; направление по тикам одинаково в игре и в записи, а объекты видят смену в тот же тик |
| 6.11.2026 | Класса в `core/` для направления нет, `TimeManager` без `class_name`; сигнал `direction_changed` шлётся только при смене | Правило из одной строки не стоит отдельного класса; `class_name` с именем автозагрузки скрыл бы синглтон |
| 6.11.2026 | `TimeManager.reset()` возвращает время вперёд, а зажатый Shift снова включает перемотку только после отпускания и нового нажатия (ответ команды: сброс уровня да) | После сброса R игрока не должно сразу утягивать назад; вызывать `reset()` будет сброс уровня (4.2) |
| 6.11.2026 | Пауза прерывает зажатие Shift: после паузы перемотка только по новому нажатию. Пока в «Идеях на потом» | Решение команды; паузы в игре ещё нет, а метод появится вместе с меню (4.3) |
| 6.11.2026 | Временная надпись направления `ui/debug_time_label.gd` в тестовой комнате, со стрелками и словами | Команда попросила индикацию, чтобы Shift был виден до 1.5; задача 1.5 заменит её индикатором на устройстве и удалит файл |
| 6.11.2026 | Путь `TimeManager` в строке «Файлы» задачи 1.2 исправлен с `game/core/` на `game/autoload/` | Узел и синглтон в `core/` нельзя (CLAUDE.md, «Layout»); сама строка «Состав» уже называла `autoload/` |
| 6.11.2026 | Деления на треки Core и Content нет: в `progress.md` одна секция «Сейчас» и одна строка «Дальше», очереди нет, в карточках задач нет поля «Трек»; задачи идут по `roadmap.md` | Решение команды: пока всё делают двое без ролей, а устройство репозитория берём как в Crown (`pipya-hash/testone`), где так же один поток задач. Правила про «свою секцию» и «чужие файлы» убраны; двое по-прежнему берут задачи с разными файлами |
| 6.11.2026 | Из Crown перенесены навык `razbor`, помощники `helper` и `reader`, `run_tests.bat` и `.gitattributes`. `CLAUDE-FREE.md` и раздел «Бесплатная версия» не перенесены | CLAUDE.md уже отправлял мелочи в `razbor` и помощникам, а файлов не было. Версия для бесплатного плана ждёт ответа команды |
