# Как работать с чатами

Памятка для двоих. Claude не помнит прошлые чаты: память проекта — файлы в репозитории. [CLAUDE.md](../CLAUDE.md) Claude читает сам, [progress.md](progress.md) — по первому сообщению. Один чат — одна задача — один pull request (PR).

## Главное

1. **Чат кончается на PR.** Правки по отзыву и новая работа — в новом чате. В старом можно задать только короткий вопрос, пока не прошёл час.
2. **Задачи, которые меняют правила времени или то, что видит игрок, — сначала план.** Claude пишет, что увидит игрок, что решит сам и какие у него вопросы, и ждёт вашего «ок».
3. **Каждый работает в своём треке.** Core — код времени, Content — уровни, арт, звук, плейтесты. Вашу задачу и файлы видно в очереди в [progress.md](progress.md).
4. **Модель и усилия — по задаче**, по таблице ниже. Обычная задача — Opus 5.5 с усилиями high, не max.
5. **Отзыв — одним сообщением**, по пунктам, главное первым.
6. **Сливайте PR до следующего чата**, иначе новый чат этой работы не увидит.
7. **Срок горит — режем по списку** из [roadmap.md](roadmap.md), а не придумываем на ходу.

## Почему так

Шаг Claude — это одно действие: прочитать файл, запустить тесты. На каждом шаге Claude заново читает всю историю чата, а обычная задача — это 100–200 шагов. Поэтому:

- чем длиннее чат, тем дороже каждый шаг;
- после часа тишины первое сообщение заново записывает всю историю, а новый чат начинается дёшево;
- всё, что прочитано в начале чата, повторяется в каждом шаге. Поэтому progress.md короткий, а журнал и решения лежат в [history.md](history.md);
- на усилиях max размышления — больше половины всего, что пишет Claude.

## Первое сообщение

Обычная задача с правилами времени или с тем, что видит игрок. Номер писать не нужно: Claude берёт следующую задачу вашего трека из `docs/progress.md` (секция «Дальше») и читает её раздел в `docs/roadmap.md`. Укажите только трек, Core или Content:

```text
Это проект Shift Time. Прочитай docs/progress.md и раздел следующей задачи моего трека (<Core или Content>) в docs/roadmap.md.
Напиши план: что увидит игрок, что решишь сам, вопросы. Жди моего «ок».
```

Техническая задача — тесты, сборка, CI. Вторая строка: «Напиши план в 3–5 строк и делай».

Не следующая, а другая задача — вместо «следующей задачи моего трека» напишите «задачи 2.3» (номер из `docs/roadmap.md`).

Уровень (Content). Карточку тоже искать не нужно: это следующая задача-уровень из очереди:

```text
Это проект Shift Time. Прочитай docs/progress.md, раздел следующей задачи моего трека (Content) в docs/roadmap.md и карточку её уровня в docs/levels/.
Собери сцену уровня и тест решения по карточке. Сначала план в 3–5 строк, жди «ок».
```

Отзыв на прошлую задачу:

```text
Это проект Shift Time. Прочитай docs/progress.md.
Отзыв на задачу <номер>, её PR слит:
1. <главное>
2. <остальное>
Поправь, потом тесты и PR.
```

Вопрос без изменений:

```text
Это проект Shift Time. Ничего не меняй. Объясни, как устроена запись истории.
```

Конфликт в PR («This branch has conflicts»):

```text
Это проект Shift Time. Реши конфликт в PR №<номер>: оставь изменения обеих сторон.
```

«Прочитай CLAUDE.md» писать не нужно: Claude читает его сам.

## Конец чата

Напишите «заканчиваем» или дождитесь, пока задача будет готова. Claude:

1. запускает оба теста — они зелёные;
2. обновляет вашу секцию «Сейчас» в progress.md, журнал и решения в history.md и отмечает закрытые критерии готовности;
3. делает коммит, пуш и PR с описанием по-русски: что изменилось и как проверить;
4. ждёт проверку «Tests» на PR, а последним сообщением предлагает две-три задачи из очереди для вас, одной строкой пишет, что осталось второму, и даёт первое сообщение для следующего чата с моделью и усилиями.

Потом слейте PR: на его странице на GitHub — Merge pull request → Confirm merge. Сливайте, когда проверка «Tests» внизу страницы зелёная. Красная — откройте новый чат: «Почини проверку в PR №…». Сломалось после слияния — кнопка Revert на странице слитого PR вернёт всё как было.

Сливайте PR, даже если задача не закончена. Тогда в progress.md будет передача — что сделано, что осталось, какие файлы, — и следующий чат продолжит с неё.

## Когда вас двое

- **Разные файлы.** В очереди в progress.md у каждой задачи есть колонка «Файлы». Берите одновременно только задачи, чьи файлы не пересекаются. Каждый уровень лежит в своей сцене, поэтому два уровня можно делать параллельно.
- **Разные секции.** В progress.md у каждого трека своя секция «Сейчас». Чат правит только свою.
- **Общее решается вдвоём.** Ворота недели, срез по списку урезания, пять решений T0 и всё, что меняет правила времени. Решение записывается в history.md.
- **Сливайте чаще.** Чем дольше PR висит, тем вероятнее конфликт. После слияния напишите второму, чтобы он подтянул `main`.
- **Один PR — один трек**, за исключением задач с пометкой «Оба».

## Когда новый чат

- PR готов — следующий шаг в новом чате, даже правки по той же задаче.
- Вернулись после перерыва больше часа — новый чат, а не старый.
- Чат начал путаться и забывать — напишите «заканчиваем» и начните новый.
- Короткий вопрос сразу после PR, пока не прошёл час, можно задать в старом чате.

Следить за PR после зелёной проверки Claude не нужно: каждое уведомление будит чат, и он перечитывает всю свою историю. Предложит следить — ответьте «не надо».

## Модель и усилия

Модель и уровень усилий (effort) выбираются в приложении.

| Что делаем | Модель | Усилия |
| --- | --- | --- |
| Новая система времени: запись, ветки, вода | Opus 5.5 | high |
| Сцена уровня, объект или правки по готовому плану, починка проверки | Sonnet 5.5 или Opus 5.5 | high |
| Карточки уровней, тексты, документы, перенос чисел в data | Sonnet 5.5 | medium |
| Вопрос «объясни, как устроено» | Sonnet 5.5 | medium |
| Трудный баг в истории, архитектура, план после срыва ворот | Opus 5.5 | max |

- **Sonnet 5.5** вдвое дешевле Opus за ответы и запись, а чтение истории у них стоит одинаково.
- **max** — только для трудного: на нём Claude дольше размышляет и склонен передумывать.
- Если упрётесь в лимит Opus, можно продолжать на Sonnet. Лимит на 5 часов и на неделю общий для всех моделей.
- Большие задачи начинайте сразу после сброса лимита, а мелкие — документы, вопросы — в конце окна.

## Отзыв

- Поиграйте 5 минут, потом напишите всё одним сообщением, по пунктам: сначала то, что мешает играть, потом мелочи, потом идеи.
- Просите конкретное: не «сделай загадку интереснее», а «в уровне 03 платформа должна ждать на верхней точке на секунду дольше».
- Claude пошёл не туда — остановите сразу и поправьте.
- Новая идея посреди задачи — в «Идеи на потом» в [roadmap.md](roadmap.md), а не в код.

## Плейтест

В неделе 3 дайте 2–3 людям пройти уровни без объяснений. Не подсказывайте, смотрите, где застряли. Записывайте в `docs/playtest.md`: уровень, где остановились, что поняли неверно, что сказали. Это самый ценный материал недели 4.

## Замер

Раз в неделю попросите любой чат: «Запиши цену прошлых чатов». Он возьмёт её из счётчика Claude Code и впишет в колонку «Цена» журнала в history.md. Так будет видно, что сработало: усилия high вместо max, Sonnet вместо Opus, короткие чаты.
